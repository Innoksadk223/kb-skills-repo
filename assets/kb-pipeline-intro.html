kb-skills-repo 全流程

从一堆 PDF，
到一篇有底气的论文大纲

这套技能生态把"读文献 → 建知识库 → 查证据 → 构思论文"拆成一条流水线。每个环节由一个专门的技能负责，各管一段，互不越界。

1先看全景：六个环节一条线

上游三个环节负责"把文献变成知识"，下游三个环节负责"把知识用起来"。

🔎找文献academic-search
📄转 MarkdownMinerU 等
📖深度精读deep-reading
🕸️编成 wikikarpathy-wiki
🗂️建索引查证据SiliconFlow-rag
📝论文大纲wiki-paper-outline

这条线不是每次都从头走到尾——中间有个"总调度"技能 social-science-km，它看你的需求和材料状态，决定从哪个环节进、走到哪个环节停（第 4 节详述）。

2所有东西放在哪？一套固定目录

整个生态共享一个目录约定：原始文献只读不动，加工产物全部放在旁边的"知识库"文件夹里，一层一层往上叠。

你的文献文件夹/ ← 原始 PDF、Word…（只读，永远不改）
你的文献文件夹（知识库）/
├── reading_dossiers/ ← 深读档案：精读长书难文后的笔记
├── wiki/
│ ├── raw/ ← 文献转成的 Markdown 全文（唯一证据层）
│ ├── claims/ concepts/ debates/ … ← 知识图谱：论点页、概念页、争论页
│ └── index.md · log.md ← 目录和操作日志
├── 检索索引/ ← RAG 索引：raw 一套、wiki 一套
└── outlines/ ← 论文大纲（最新加入）

3逐个环节拆开讲

每张卡片：这个环节干什么、由哪个技能负责、吃进什么、吐出什么。

🔎

环节 0（可选）：找文献

academic-search（上游安装）

手头材料不够时才走这一步：按主题搜学术文献，列出候选清单（标题、年份、引用数、是否有合法全文），你点头之后才下载。只收合法可得的全文，绝不绕付费墙。

研究方向→文献文件夹里的新 PDF
📄

环节 1：把文献变成机器能读的文本

mineru-document-extractormarkitdown

PDF（尤其是扫描版、古籍影印、带表格公式的论文）交给 MinerU 做 OCR 和结构还原；干净的 Word/PPT/网页等交给轻量的 MarkItDown。全部转成 Markdown 存进 wiki/raw/，并记一本转换台账——哪个文件转了、用了什么工具、有没有失败。

PDF / Word / PPT…→wiki/raw/*.md
📖

环节 2：该精读的先精读

deep-reading-to-wiki

不是所有材料都能直接进图谱。转完后先"体检"：整本书、长章节、理论很重的文章，如果跳过精读直接总结，很容易变成浅薄的一句话概括。这类材料先走深度精读，逐段读完产出"深读档案"——论证地图、关键引文的位置锚点、语境风险提示。

  • 短小、低风险的材料可以跳过，直接进下一环节
  • 档案只是"读书笔记"，不算正式知识，也不算原始证据
wiki/raw/ 长文→reading_dossiers/ 深读档案
🕸️

环节 3：编成一张知识图谱

karpathy-wiki

把深读档案和原文提炼成互相链接的 wiki 页面：claims/（一条条论点卡片：主张、支持、反对、限定条件）、concepts/（概念）、debates/（多方争论）、comparisons/（辨析）等。页面之间用类型化关系连线——谁支持谁（supports）、谁反驳谁（contradicts）、论证从哪推出（derives_from）、论证顺序怎么展开（follows）。

这张关系网是整个生态的心脏：后面的检索扩展、论文大纲的冲突论点分析，全都是顺着这些线走出来的。
raw + 深读档案→wiki/claims、concepts、debates…
🗂️

环节 4：建索引，随问随查

SiliconFlow-rag

给知识库装上"搜索引擎"：raw 全文一套索引，wiki 图谱页一套索引。之后你随时提问，它按问题类型自动选路——

  • 查原文出处（"这段话在哪篇文献？"）→ 直接搜 raw
  • 概念性问题（"X 和 Y 什么关系？"）→ 先搜 wiki 定位论证路径，再回 raw 拿证据
  • 高要求写作 → deep 档：多查询改写 + 精排 + 上下文扩展全开
  • 文件变了会自动提醒你增量更新索引，避免用旧索引答题
你的问题→Wiki 路径 + 原文证据
📝

环节 5：像导师一样陪你定论文大纲

wiki-paper-outline

知识库建好后的"收获环节"。它顺着图谱关系网找到相关论点，用 RAG 检索拿证据，先给你一份骨架（核心论点候选、章节树、冲突论点清单），然后像导师一样逐个追问——论点选哪个？反对意见怎么应对？——方向定了才逐章填成完整大纲，每条要点都带出处，证据不够的地方诚实标缺口。

wiki + 检索索引→outlines/大纲.md

4总调度：social-science-km

它不亲自干活，而是看你的需求选路线、盯质量关卡。几个典型场景：

你说……它安排的路线
"帮我把这堆 PDF 建成知识库"环节 1 转换 → 环节 2 精读体检 → 环节 3 编 wiki → 环节 4 建索引
"XX 的原文出处在哪？"直接环节 4 检索，不重新加工任何材料
"我想补充一些关于 XX 的内容"缺口驱动扩展：先检索现有材料找候选来源 → 不够再找新文献 → 精读 → 补进 wiki → 更新索引
"帮我构思一篇关于 XX 的论文"路由到环节 5 wiki-paper-outline
"这个 wiki 怎么感觉很浅？"回炉：给关键材料补做深读档案，再修订 wiki 页面

它还守着几道硬规矩：原始文献永远只读；长书难文不精读不许进图谱；每个正式论点必须能追溯到原文；动索引、批量转换、大改 wiki 之前都先问你。

5技能名册速查

紫色 = 本仓库自带；橙色 = 需要从上游另行安装。

social-science-km总调度

看需求选路线，守质量关卡，管目录约定。一切从它进。

deep-reading-to-wiki精读

长书难文的深度精读，产出带原文锚点的深读档案。

karpathy-wiki图谱

把材料编成互链的 wiki：论点、概念、争论，加类型化关系网。

SiliconFlow-rag检索

建双索引（raw + wiki），按问题类型路由检索，自动查新旧。

wiki-paper-outline大纲

导师式讨论 + 自循环检索，产出带出处、标缺口的论文大纲。

academic-search找文献

按主题搜学术文献，合法获取全文。材料不够时用。

mineru-document-extractor转换

PDF/扫描件/古籍的 OCR 与结构化转换主力。

markitdown转换

Word、PPT、网页等干净格式的轻量转换。
